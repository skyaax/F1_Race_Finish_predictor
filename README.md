# 🏎️ F1 Race Finish Predictor

An end-to-end Formula 1 data engineering and machine learning project that **extracts** race & qualifying data from the official F1 API (via FastF1), stores it in a **SQLite** database, performs **exploratory data analysis**, trains a **Linear Regression** model, and serves predictions through a **FastAPI** REST API — all containerisable with **Docker**.

## Project Overview

The goal of this project is to **predict a driver's race finish position** based on qualifying performance and historical circuit data. The pipeline covers four F1 seasons (**2021 – 2024**) and includes:

1. **Data Engineering** — schema design, database creation, and an ETL pipeline that pulls data from the FastF1 library.
2. **Data Analysis** — a Jupyter notebook with rich EDA covering qualifying vs. race correlations, driver dominance analysis (Max Verstappen era), constructor comparisons, and the iconic 2021 title fight.
3. **Machine Learning** — model selection across Linear Regression, Ridge, Random Forest, and Gradient Boosting; final model achieves **MAE ≈ 2.2 positions** and **R² ≈ 0.72**.
4. **Model Serving** — a FastAPI application that loads the trained model and exposes a `/predict` endpoint.

## Data Pipeline (ETL)

The ETL process lives in the `de/` directory and runs in two steps:

### 1. Schema Creation (`de/db_creation.py`)

Creates (or recreates) all 6 tables with proper primary keys, foreign keys, and uniqueness constraints.

```bash
python de/db_creation.py
```

### 2. Data Extraction & Loading (`de/ETL.py`)

- Iterates over the **2021–2024** seasons using the [FastF1](https://docs.fastf1.dev/) library.
- For each Grand Prix round, extracts:
  - **Circuit** information (location, country)
  - **Driver** details (name, number, abbreviation, nationality)
  - **Constructor** data (team name)
  - **Qualifying results** (Q1, Q2, Q3 lap times)
  - **Race results** (grid position, finish position, points, status)
- Uses `INSERT OR REPLACE` to handle reruns gracefully.
- Caches FastF1 API responses locally in `fastf1_cache/` for faster subsequent runs.

```bash
python de/ETL.py
```

## Data Analysis & EDA

The Jupyter notebook (`data_analysis-machine_learning/f1.ipynb`) contains a thorough analysis structured as follows:

### Data Preparation
- Loads data from SQLite with a multi-table SQL `JOIN` query
- Handles missing values (262 null finish positions dropped, qualifying times converted)
- Converts qualifying lap times to seconds using the `utility_script/util.py` helper

### Exploratory Analysis
The notebook investigates several key questions:

| Analysis | Visualisation |
|----------|---------------|
| **Qualifying vs. Race finish correlation** | Heatmap — shows P1 qualifier finishes on podium 55 out of 70 times |
| **Average gained positions per driver** | Bar chart — identifies best overtakers (e.g. Franco Colapinto) |
| **Total points by driver (2021–2024)** | Bar chart + Waffle chart |
| **Max Verstappen vs. entire constructor field** | Bar chart — Max individually outscores all teams except Red Bull (2022–2024) |
| **2021 Championship battle** | Cumulative points line chart — Verstappen vs. Hamilton title fight |
| **Position gain/loss distributions** | Violin plots per driver |
| **Qualifying & finishing consistency** | Violin plots of grid & finish positions |
| **Feature correlation** | Heatmaps — including circuit-specific averages |

### Key Insights
- Qualifying position is the single strongest predictor of race finish.
- Max Verstappen (2022–2024) individually outscored every constructor except his own team.
- Circuit-specific features (average finish, average points at a track) show strong correlation with results.

## Machine Learning Model

### Features Used

| Feature              | Description                                        |
|----------------------|----------------------------------------------------|
| `grid_position`      | Starting grid position from qualifying             |
| `q2_seconds`         | Q2 qualifying lap time in seconds                  |
| `q3_seconds`         | Q3 qualifying lap time in seconds                  |
| `circuit_avg_finish` | Driver's historical average finish at that circuit  |
| `circuit_avg_points` | Driver's historical average points at that circuit  |

### Target Variable

`finish_position` — the driver's final race classification.

### Models Evaluated

| Model                      | MAE   | R²    |
|----------------------------|-------|-------|
| **Linear Regression**      | ~2.24 | ~0.69 |
| **Ridge Regression**       | ~2.24 | ~0.69 |
| Random Forest              | —     | —     |
| Gradient Boosting          | —     | —     |

Linear and Ridge Regression outperformed the ensemble methods. The final model uses **Linear Regression** with hyperparameters optimised via `GridSearchCV`.

### Final Model Performance (2024 Predictions)

| Metric                 | Value  |
|------------------------|--------|
| **Mean Absolute Error** | ~2.2 positions |
| **R²**                 | ~0.72  |

> An MAE of ~2.2 positions is strong given the inherently unpredictable nature of racing (mechanical failures, weather, safety cars, incidents).

The trained model is serialised to `model_f1.joblib` and the full prediction results (actual vs. predicted for every 2024 race) are exported to `results/predictions_table.csv`.

## API

The FastAPI application (`main.py`) serves the trained model as a REST API.

### Endpoints

| Method | Path       | Description                          |
|--------|------------|--------------------------------------|
| `GET`  | `/`        | Health check — returns API status    |
| `POST` | `/predict` | Predict race finish position         |

### Request Schema (`/predict`)

```json
{
  "grid_position": 3,
  "q2_seconds": 89.5,
  "q3_seconds": 88.2,
  "circuit_avg_finish": 4.5,
  "circuit_avg_points": 12.0
}
```

### Response

```json
{
  "prediction": 3
}
```

### Running Locally

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

Interactive docs are available at `http://localhost:8000/docs` (Swagger UI).

## Getting Started

### Prerequisites

- Python 3.10+
- pip

### Installation

```bash
# Clone the repository
git clone https://github.com/<your-username>/f1_project.git
cd f1_project

# Create a virtual environment
python -m venv .venv
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

### Full Pipeline Run

```bash
# 1. Create the database schema
python de/db_creation.py

# 2. Run the ETL pipeline (downloads data from FastF1 — takes a few minutes)
python de/ETL.py

# 3. Open the analysis notebook
jupyter notebook data_analysis-machine_learning/f1.ipynb

# 4. Start the API server
uvicorn main:app --host 0.0.0.0 --port 8000
```
